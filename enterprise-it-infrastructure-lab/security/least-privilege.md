# Μοντέλο Ελάχιστων Δικαιωμάτων (Least Privilege)

## Αρχή

Κάθε λογαριασμός — ανθρώπινος ή service — έχει μόνο την πρόσβαση που απαιτείται για τη δουλειά του, και τίποτα παραπάνω. Αυτό περιορίζει τη ζημιά που μπορεί να προκαλέσει ένας compromised λογαριασμός ή ένα ειλικρινές λάθος.

## Υλοποίηση σε Αυτό το Περιβάλλον

### Τυπικοί Χρήστες

- Οι τυπικοί χρήστες domain **δεν** είναι τοπικοί administrators στα δικά τους μηχανήματα.
- Η πρόσβαση στα shares τμημάτων παρέχεται μόνο μέσω security groups τμημάτων (`GG_Finance`, `GG_HR` κ.λπ.) — ποτέ απευθείας σε μεμονωμένους λογαριασμούς χρηστών.
- Οι τυπικοί χρήστες δεν μπορούν να εγκαταστήσουν λογισμικό (επιβάλλεται μέσω GPO / χωρίς τοπικά δικαιώματα admin).

### Προσωπικό IT

- Τα μέλη του `GG_IT_Admins` παίρνουν **τοπικά** δικαιώματα administrator στο δικό τους workstation (μέσω GPO Restricted Groups με στόχευση στο OU IT) — όχι δικαιώματα admin σε επίπεδο domain.
- Τα δικαιώματα Domain Admin ανήκουν σε ένα μικρό, ξεχωριστό σύνολο ονομαστικών λογαριασμών (σε παραγωγικό περιβάλλον, ιδανικά το πολύ 2 άτομα, που χρησιμοποιούνται μόνο για αλλαγές σε επίπεδο domain, ποτέ για καθημερινό email/πλοήγηση).
- Το προσωπικό IT χρησιμοποιεί ξεχωριστό λογαριασμό `-adm` για προνομιακές εργασίες, διαφορετικό από τον καθημερινό λογαριασμό εργασίας που χρησιμοποιείται για email και γενική δουλειά (διαχωρισμός καθηκόντων, μειώνει τον κίνδυνο από phishing κατά του καθημερινού λογαριασμού).

### Service Accounts

- Βρίσκονται σε ξεχωριστό OU `Service Accounts`, εξαιρούνται από GPOs προσανατολισμένα σε interactive logon (screen lock κ.λπ.).
- Κάθε service account περιορίζεται στα ελάχιστα δικαιώματα που απαιτεί η συγκεκριμένη εργασία του (π.χ. ένας service account backup έχει read πρόσβαση σε shares, όχι write/delete).
- Τα passwords των service accounts είναι μεγάλα, τυχαία, και ανανεώνονται σε τεκμηριωμένο πρόγραμμα (ή αντικαθίστανται με Group Managed Service Accounts — gMSA — σε παραγωγικό περιβάλλον).

## Επανεξετάσεις Πρόσβασης

| Επανεξέταση | Συχνότητα | Υπεύθυνος |
|---|---|---|
| Συμμετοχή σε groups τμημάτων | Τριμηνιαία | Υπεύθυνος τμήματος + IT |
| Συμμετοχή σε GG_IT_Admins / προνομιακά groups | Τριμηνιαία | IT Manager |
| Αναφορά ανενεργών λογαριασμών (μέσω [`Export-ADUsers.ps1`](../automation/Export-ADUsers.ps1)) | Μηνιαία | IT Support |
| Λίστα πρόσβασης VPN | Τριμηνιαία | IT Manager |

## Παράδειγμα: Γιατί Έχει Σημασία

Στο [Ticket INC-001](../it-support/tickets/INC-001.md), το πρόβλημα πρόσβασης ενός χρήστη αποδείχθηκε ότι ήταν **έλλειψη** δικαιώματος μετά από αλλαγή ρόλου — η άλλη όψη του least privilege είναι να διασφαλίζουμε ότι οι επανεξετάσεις πρόσβασης εντοπίζουν τόσο τους υπερ-δικαιωματούχους **όσο και** τους υπο-δικαιωματούχους λογαριασμούς, καθώς και οι δύο περιπτώσεις προκαλούν πραγματικό επιχειρησιακό αντίκτυπο.
