# KB-002 — Διάγνωση Επαναλαμβανόμενων Lockouts Λογαριασμού

**Κατηγορία:** Διαχείριση Λογαριασμών / Ασφάλεια
**Κοινό:** IT Support L1/L2

## Σύμπτωμα

Ο λογαριασμός του χρήστη κλειδώνει επανειλημμένα, μερικές φορές μέσα σε λίγα λεπτά από το ξεκλείδωμα, παρόλο που ο χρήστης επιμένει ότι εισάγει το σωστό password.

## Γιατί Συμβαίνει Αυτό

Τα επαναλαμβανόμενα, γρήγορα lockouts προκαλούνται σχεδόν πάντα από ένα **παλιωμένο cached διαπιστευτήριο** κάπου που κάνει retry αυτόματα στο παρασκήνιο — όχι επειδή ο χρήστης πληκτρολογεί λάθος το password. Συχνές πηγές, με φθίνουσα σειρά συχνότητας:

1. Μια δεύτερη συσκευή (κινητό, προσωπικό laptop, tablet) με mapped drive, mail profile, ή αποθηκευμένο διαπιστευτήριο Wi-Fi που εξακολουθεί να χρησιμοποιεί το παλιό password
2. Ένα scheduled task ή service που τρέχει με τον λογαριασμό του χρήστη και έχει αποθηκευμένο το παλιό password
3. Μια κινητή συσκευή με παλιό προφίλ ActiveSync/Exchange
4. Διαπιστευτήρια αποθηκευμένα σε browser για μια εσωτερική web εφαρμογή που ο χρήστης έχει ξεχάσει

## Βήματα Διάγνωσης

1. Ξεκλειδώστε τον λογαριασμό: `Unlock-ADAccount -Identity <username>`
2. Στον domain controller, βρείτε τον **υπολογιστή-πηγή** των λανθασμένων προσπαθειών password χρησιμοποιώντας το Event Viewer → Security log, φιλτραρισμένο στο **Event ID 4740** (lockout λογαριασμού). Οι λεπτομέρειες του event περιλαμβάνουν το "Caller Computer Name."
   - Αν το DC01 δεν διατηρεί αρκετό ιστορικό logs, ελέγξτε το `netwkstasec.log` αν είναι ενεργό το Netlogon debug logging, ή χρησιμοποιήστε το εργαλείο Account Lockout Status.
3. Συγκρίνετε τον υπολογιστή-πηγή με τις γνωστές συσκευές του χρήστη. Αν δεν είναι ο κύριος υπολογιστής εργασίας του, αυτός είναι ο ένοχος.
4. Ζητήστε από τον χρήστη να ελέγξει/καθαρίσει αποθηκευμένα διαπιστευτήρια στη συσκευή που εντοπίστηκε:
   - Windows: Control Panel → Credential Manager, και `net use * /delete`
   - Κινητό: αφαιρέστε και προσθέστε ξανά το προφίλ email/VPN με το νέο password
5. Επιβεβαιώστε ότι δεν υπάρχουν άλλα lockouts την επόμενη ώρα.

## Escalation

Αν το Event ID 4740 δεν δείχνει προφανή συσκευή, ή τα lockouts συνεχίζονται μετά τον καθαρισμό όλων των γνωστών cached διαπιστευτηρίων, κάντε escalation στο L2 — αυτό μπορεί να υποδεικνύει πραγματική προσπάθεια brute-force κατά του λογαριασμού και πρέπει να διερευνηθεί ως πιθανό περιστατικό ασφάλειας, όχι απλά ενόχληση.
