# Πλάνο Disaster Recovery

## Εύρος Εφαρμογής

Αυτό το έγγραφο καλύπτει τις διαδικασίες ανάκτησης για το πιο κρίσιμο σενάριο αστοχίας σε αυτό το περιβάλλον: **απώλεια του DC01**, του μοναδικού domain controller που τρέχει AD DS, DNS, και DHCP. Ο σχεδιασμός με μοναδικό DC είναι γνωστός κίνδυνος σε αυτό το lab (ένα παραγωγικό περιβάλλον αυτού του μεγέθους θα έπρεπε να τρέχει τουλάχιστον 2 DCs) — αυτό το πλάνο υπάρχει ειδικά λόγω αυτού του κινδύνου.

## Σενάριο: Αστοχία DC01

```
Αστοχία DC01
     │
     ▼
Εντοπισμός αστοχίας (ειδοποίηση monitoring / helpdesk αναφέρει "δεν μπορώ να συνδεθώ")
     │
     ▼
Προσδιορισμός τύπου αστοχίας: hardware, corruption, ή πρόβλημα βάσης AD
     │
     ▼
Προσπάθεια ανάκτησης επί τόπου (επανεκκίνηση, repair boot, ntdsutil)
     │
     ├── Ανακτήθηκε; → Επικύρωση υπηρεσιών → Ολοκληρώθηκε
     │
     ▼ (δεν ανακτήθηκε)
Επαναφορά από backup (System State restore σε νέο/επισκευασμένο VM)
     │
     ▼
Επαναφορά ρόλων AD DS / DNS / DHCP
     │
     ▼
Επαλήθευση ακεραιότητας replication/βάσης (dcdiag, repadmin)
     │
     ▼
Επαλήθευση ακεραιότητας ζώνης DNS και δεδομένων scope DHCP
     │
     ▼
Επανασύνδεση clients (πρέπει να είναι αυτόματη μέσω DNS SRV records
μόλις το DC01 επανέλθει στο 192.168.30.10)
     │
     ▼
Επικύρωση: οι χρήστες μπορούν να συνδεθούν, το DHCP εκδίδει leases, το DNS επιλύει
     │
     ▼
Τεκμηρίωση περιστατικού (χρονολόγιο, αιτία, επίλυση, διδάγματα)
```

## Διαδικασία Ανάκτησης Βήμα-Βήμα

1. **Εντοπισμός της αστοχίας**
   - Ειδοποίηση MON01, ή tickets helpdesk που αναφέρουν αποτυχίες ταυτοποίησης/DHCP από πολλούς χρήστες (ισχυρή ένδειξη ότι είναι υποδομή, όχι μεμονωμένο μηχάνημα)
   - Επιβεβαίωση: `Test-Connection DC01`, προσπάθεια πρόσβασης RDP/console

2. **Πρώτα προσπάθεια ανάκτησης επί τόπου** (πιο γρήγορη από πλήρη επαναφορά αν ο υποκείμενος δίσκος/VM είναι άθικτο)
   - Εκκίνηση σε Directory Services Restore Mode (DSRM) αν υποψιάζεται corruption της βάσης AD
   - Εκτέλεση ελέγχων ακεραιότητας `ntdsutil`

3. **Αν η ανάκτηση επί τόπου αποτύχει, επαναφορά από backup**
   - Στήσιμο αντικαταστάτη VM που ταιριάζει με τα αρχικά specs του DC01 (δες [`../architecture/infrastructure.md`](../architecture/infrastructure.md))
   - Εκτέλεση **authoritative System State restore** χρησιμοποιώντας το πιο πρόσφατο επαληθευμένο backup (δες [`backup-strategy.md`](backup-strategy.md))
   - Εντολή: `wbadmin start systemstaterecovery -version:<backup version> -backupTarget:<location>`

4. **Επαναφορά AD DS / DNS / DHCP**
   - Το System State restore επαναφέρει μαζί το AD DS, το SYSVOL, και τα δεδομένα ζώνης DNS (AD-integrated DNS)
   - Επανεξουσιοδότηση του DHCP server στο AD αν χρειάζεται: `Add-DhcpServerInDC`, μετά `Restore-DhcpServerv4Configuration` από την τελευταία εξαγωγή ρύθμισης DHCP

5. **Επαλήθευση ακεραιότητας**
   ```powershell
   dcdiag /v
   repadmin /replsummary
   ```

6. **Επαλήθευση DNS και DHCP**
   - Επιβεβαίωση ότι η ζώνη AD-integrated DNS φορτώθηκε σωστά και ότι βασικά records (SRV records για LDAP/Kerberos) επιλύονται
   - Επιβεβαίωση ότι τα scopes DHCP είναι ενεργά και εκδίδουν leases: `Get-DhcpServerv4Scope`

7. **Επικύρωση συνδεσιμότητας clients**
   - Δοκιμαστικό login από δείγμα client κάθε τμήματος
   - Επιβεβαίωση πρόσβασης σε file share, εφαρμογής GPO (`gpupdate /force` και μετά `gpresult /r`)

8. **Τεκμηρίωση μετά το περιστατικό**
   - Χρονολόγιο εντοπισμού → ανάκτησης → επικύρωσης
   - Βασική αιτία (αστοχία hardware, corruption, τυχαία διαγραφή κ.λπ.)
   - Ποια έκδοση backup χρησιμοποιήθηκε και πόσο παλιά ήταν (το κενό = πιθανή απώλεια δεδομένων προς επικοινωνία στα ενδιαφερόμενα μέρη)
   - Ενέργειες προς αποτροπή επανεμφάνισης (π.χ. "προσθήκη δεύτερου DC" είναι η πάγια σύσταση από αυτή την άσκηση)

## Βασική Σύσταση από Αυτή την Άσκηση

Ο μεγαλύτερος κίνδυνος που εντοπίστηκε κατά τη συγγραφή αυτού του πλάνου είναι το **μοναδικό σημείο αστοχίας (single point of failure)** του να τρέχει μόνο ένας domain controller. Το τεκμηριωμένο επόμενο βήμα για αυτό το περιβάλλον είναι η ανάπτυξη δεύτερου DC (DC02) για redundancy — αυτό το πλάνο θα ενημερωθεί μόλις υλοποιηθεί αυτό, ώστε να περιλαμβάνει τη μεταφορά/κατάληψη ρόλων FSMO ως εναλλακτικό μονοπάτι ανάκτησης.
